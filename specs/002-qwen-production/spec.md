# SPEC 002: Qwen как рабочая модель

## Контекст и цель

Владелец выбрал `qwen3.8-27b` для извлечения находок через внутренний Open WebUI.
В открытом сравнении на материале ФОМ Qwen вернул семь содержательно подходящих
находок, GPT — шесть. Действующий валидатор принял только пять из семи находок
Qwen: он не поддерживает словесную долю «две трети» как приблизительно 67%, а
для находки о молодёжи модель указала базу не дословным фрагментом. Владелец
подтвердил, что словесные доли надо переводить в проценты, предпочитает
формулировку «взрослых россиян» вместо «населения 18+» и требует не опускать
указанный в источнике период.

Рабочий worker сейчас использует `gpt-6.1-sol`, лимит 20 находок, 6000 токенов
и тайм-аут 90 секунд. Владелец выбрал Qwen без рассуждений и сохранил лимит 20.
Во внутреннем API параметр `chat_template_kwargs: {"enable_thinking": false}`
дал 0 токенов рассуждения. На материале ФОМ получены семь находок за 23,5 с
при 2443 выходных токенах; на длинном материале НАФИ — 15 находок за 42,6 с
при 4810 выходных токенах. Оба ответа завершились без обрезания при лимите
10 000 токенов и тайм-ауте 240 с. Без рассуждений Qwen всё ещё пропускает
период в части формулировок, поэтому нужен контроль качества промпта.

## Ожидаемый результат и пользователи

- Исследователь получает проверяемые процентные находки в web, Telegram и Mini
  App с полнотой не ниже согласованной контрольной выборки.
- Оператор запускает worker с `qwen3.8-27b` через внутренний Open WebUI без
  изменения ключа и без обращения к OpenRouter.
- При слишком длинном или некорректном ответе worker сохраняет прежние
  находки и сообщает безопасную диагностическую причину.

## Объём

1. Задать рабочий ID `qwen3.8-27b` в локальной конфигурации и шаблоне/описании
   настройки для следующего запуска. Секреты не записывать в Git.
2. Для Qwen передавать `chat_template_kwargs: {"enable_thinking": false}`.
   Рабочий лимит — 20 находок на материал, 10 000 выходных токенов, тайм-аут
   240 секунд. Не менять единый API Open WebUI и строгую JSON-схему.
3. Поддержать явно сформулированные словесные доли людей, когда исходный текст
   и человеческая база проверяемы. Числовое значение вычислять
   детерминированно из простой дроби и округлять до целого процента; для
   неточного результата писать «около», например «две трети» → «около 67%».
   В цитате и поле `source_value` сохранить исходное словесное выражение;
   вычисленное значение в `value` пометить как приблизительное в `summary`.
   Не принимать произвольные числа, которых нельзя вывести из цитаты.
4. Сохранить проверку цитаты, значения и базы. Ответы, не прошедшие проверку,
   не публиковать. Для уточнённой подгруппы модель должна указывать дословный
   фрагмент базы, например «среди молодежи», а не нормализованное слово.
5. Уточнить промпт: для широкой аудитории 18+ предпочитать «взрослых россиян»,
   если география РФ подтверждена; указывать период в формулировке находки,
   когда он есть в материале и влияет на смысл показателя. Не домысливать
   период при его отсутствии. Изменение промпта получает новую версию.
6. Обновить PRD, методологию, рабочую документацию и проверку качества.
   Повторную обработку
   архива не запускать в рамках этой задачи.

## Проверка результата

- На сохранённом материале ФОМ от 10 ноября 2026 года Qwen возвращает полный
  структурированный ответ без обрезания и без токенов рассуждения. Все семь
  содержательно одобренных владельцем находок проходят локальную проверку,
  включая «две трети» → «около 67%» и 13% среди молодёжи.
- В формулировке находки о 13% молодёжи указан период «за последние два-три
  месяца». Широкая взрослая аудитория названа естественно и без смены базы.
- На согласованной контрольной выборке нет ошибок тайм-аута, обрезанного JSON
  и неподтверждённых цитат; один материал даёт не более 20 находок.
- На ответе API для Qwen `reasoning_tokens=0`. Если внутренний сервер перестанет
  применять переключатель, контрольный прогон сообщает об этом.
- Полный набор автоматических тестов и `git diff --check` проходят.
- Рабочий ключ не попадает в код, документацию, тестовые данные и коммиты.

## Подтверждённые решения владельца

- Рабочая модель — Qwen3.8-27B без генерации рассуждений.
- Максимум — 20 находок на материал.
- Словесные доли переводить в проценты; «две трети» показывать как
  «около 67%».

## Границы

- Не менять источники и интерфейсы. Для аудита использовать существующие поля
  `source_value` и `evidence`; миграция БД не нужна.
- Не публиковать, не делать push и deploy без отдельного указания владельца.
- Не переписывать старые записи автоматически. Перезапуск архива требует
  отдельного решения.

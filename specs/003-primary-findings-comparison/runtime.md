# SPEC 003: рабочие правила 30/5

Окружение worker после обновления:

```text
MODEL=qwen3.8-27b
PROMPT_VERSION=audience-primary-findings-v7
MAX_FINDINGS_PER_MATERIAL=30
REPROCESS_OLD=0
REPROCESS_MATERIAL_IDS=
```

Старые значения PROMPT_VERSION v5/v6 новый worker отвергает до обращения к БД
и модели. Это защищает сохранённую интерпретацию от записи нового формата под
старым именем. Идентификатор модели, ключ и endpoint не меняются.

Проверенные находки (до 30) сохраняются целиком. Дополнительные поля:
population_scope, is_primary, primary_rank, primary_reason,
is_demographic_breakdown. Они nullable для совместимости с прежними строками.
is_primary=false означает явное исключение из выдачи, NULL — старую запись.

Основных не более пяти на материал. После валидации приоритет у базовых,
условные допускаются при отсутствии пригодных базовых. Состав выборки по
возрасту/географии исключается из основных. Модельные выборы без объяснения
не публикуются; система не дополняет набор до пяти автоматически.

Web, Mini App, /start, /status и Telegram-сводка используют одну SQL-политику
с ограничением по material_id и prompt_version. Для legacy-строк без разметки
видны первые пять подходящих находок в исходном порядке. Это не новая смысловая
разметка архива; для неё нужен отдельно разрешённый контрольный reprocess.
Старые интерпретации не удаляются и при ошибке модели остаются текущими.

В деталях Mini App показаны классификация базы и причина выбора основной.
Общая лента показывает только основные, не весь сохранённый массив.

Миграция схемы только добавляет nullable-поля и индекс. Архив автоматически
не обрабатывается; версия переключается для материала после успешного
транзакционного сохранения новой интерпретации. До внедрения выполнить
capture прежнего релиза по `rollback.md`; фактический deploy требует отдельного
указания владельца.

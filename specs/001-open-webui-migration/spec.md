# SPEC 001: переход на внутренний Open WebUI

## Контекст и цель

Сейчас `worker` отправляет материалы в OpenRouter. Владелец хочет использовать
внутренний LLM-контур `https://inside.omirussia.ru/` и полностью отключить
OpenRouter. Результат функции — автоматическая обработка новых материалов через
Open WebUI с прежними правилами отбора, валидации и публикации находок.

## Пользователи и ожидаемый результат

- Исследователь продолжает получать проверяемые процентные характеристики
  людей в web, Telegram и Mini App без изменения пользовательского сценария.
- Оператор проекта задаёт адрес внутреннего сервиса, API key и ID модели через
  переменные окружения. Секрет не хранится в репозитории и отчётах.
- При ошибке API или некорректном ответе материал не публикует новые находки;
  причина доступна в безопасной диагностике.

## Объём функции

- Перевести единственный вызов LLM в `worker` на
  `POST https://inside.omirussia.ru/api/chat/completions` с Bearer API key.
- Удалить из рабочего пути OpenRouter, включая его URL, ключ и особые параметры
  запроса; запасного обращения к нему не делать.
- Использовать точный ID модели, доступной пользователю API key. Его можно
  определить запросом `GET /api/models` после настройки доступа.
- Сохранить существующие промпт, локальную проверку JSON, ограничения объёма
  текста и ответа, правила отбора и запись данных. Структурированный ответ
  проверить на выбранной модели: использовать поддерживаемый режим JSON и
  сообщать об ошибке, если получить пригодный результат нельзя.
- Перевести `quality_check.py`, `docker-compose.yml`, `.env.example`, README и
  относящиеся к вызову тесты на новое имя провайдера и переменные настройки.
- Не менять источники, БД, интерфейсы и состав находок.

## Критерии готовности

1. Ни `worker`, ни `quality_check.py` не обращаются к OpenRouter и не требуют
   `OPENROUTER_API_KEY`.
2. Запрос к Open WebUI проходит с заданным ключом и моделью; ответ разбирается
   текущим валидатором. Ошибки авторизации, доступа к модели, HTTP и некорректный
   JSON фиксируются без раскрытия ключа.
3. Локальная проверка качества обрабатывает несколько известных материалов
   без записи в PostgreSQL. Для принятых находок процент, база и цитата
   подтверждаются исходным текстом; отклонённые ответы видны в отчёте.
4. Проходят полный набор автоматических тестов и `git diff --check`.

## Ограничения и открытые условия

- API key выдаётся владельцу и задаётся в секретах среды запуска, не в коде.
- Доступность `inside.omirussia.ru` из среды, где запущен worker, пока не
  подтверждена. Перед включением требуется проверить сетевой доступ.
- Точный ID модели и поддержка `response_format` внутренним развёртыванием
  пока неизвестны. Их определят через список моделей и пробный запрос.
- Контрольный прогон не заменяет решения владельца о включении рабочего worker.

## Основание

Документация Open WebUI: https://docs.openwebui.com/reference/api-endpoints/
Указания владельца: внутренний URL выше; ключ выдаётся; OpenRouter отключить.

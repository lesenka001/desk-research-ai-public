# T6: отказ при входе с собственной HTML-формы

## Проблема

После redeploy в Coolify владелец открыла страницу CRM, ввела пароль и получила
«Запрос с другого сайта отклонен». Код выдавал `Referrer-Policy: no-referrer`:
для HTML POST браузер может отправить `Origin: null`, который наша проверка
корректно отклоняет. Ошибка находится в политике ответа самой формы, а не
в пароле. Источник поведения: [MDN Referrer-Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header).

## Изменение

- Политика ответа заменена на `same-origin`. Собственная форма сохраняет Origin,
  сведения о внутреннем адресе не передаются посторонним сайтам.
- Проверки Origin:null/чужого домена и токена CSRF остаются без ослабления.
  Доверие к произвольному X-Forwarded-Host не добавляется.
- Ранний отказ на POST дренирует непрочитанное тело только до16КиБ и с таймаутом
  2с, чтобы закрытие соединения не теряло ответ403/429. Большие отклоненные
  загрузки не читаются. Уже прочитанное тело не читается повторно.

## Проверки

Полный набор: 186 тестов, OK. Добавлены HTTP-регрессии политики ответа,
входа с настоящим Origin, отказа null/чужому домену. Исходный редкий WinError10053
на ранних ответах воспроизвел также независимый проверяющий; дренирование
малых форм добавлено по результатам проверки, без изменения успешного импорта.
Независимое повторное ревью: замечаний нет, все девять HTTP-тестов прошли,
WinError10053 после исправления не повторился.

## Применение

Один коммит T6, push в существующую ветку master по разрешению владельца.
После публикации требуется redeploy в Coolify и повторное открытие `/crm`,
чтобы получить HTML с новой политикой; старую страницу входа нужно обновить.
Пароль и переменные окружения сохраняются. Схема и данные БД не изменяются.
После redeploy фактический вход владельца еще требуется подтвердить.

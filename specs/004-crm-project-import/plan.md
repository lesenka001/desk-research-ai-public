# План SPEC 004

SPEC утверждена владельцем 23 ноября 2026 года. Принят вход с одним паролем.

## Границы

Расширить существующий `web/main.py`; логика импорта — в `crm/`, без нового
сервиса и LLM. PostgreSQL хранит текущий набор проектов/решений как JSONB
и отдельную неизменяемую историю загрузок и решений. Такая структура позволяет
выполнять расчет чистой функцией и атомарно сохранять согласованный снимок.
Файлы Excel разбираются в памяти и не сохраняются на сервере.

## Порядок

1. T1: XLSX, валидация, нормализация ЦА, обновления PN, группы, IQR, решения.
2. T2: аддитивные таблицы PostgreSQL и транзакции с блокировкой записи набора;
   история содержит исходные значения строк и причины исключений без XLSX.
3. T3: один пароль из окружения, подписанная сессия с ограниченным сроком,
   CSRF, лимиты входа/файла; страницы загрузки, проверки, проектов и истории.
4. T4: контрольная выгрузка без рабочей БД, HTTP-проверки, полный набор тестов,
   независимое ревью diff, документация и отдельные локальные коммиты задач.

## Проверка

Чистые тесты включают обновления, спорную замену, постоянные исключения,
пунктуацию с числовыми ограничениями, выбор последнего PN, IQR и неизменные
повторы после решений. Хранилище проверяется на транзакции/блокировку/ошибки.
HTTP проверяется реальным локальным сервером с тестовым хранилищем: доступ,
вход, cookies, CSRF, загрузка, решения и отсутствие утечек в публичный ответ.
Полная приемка исходника: 539 строк, 25 исключений, 514 оставшихся.

Наличие PostgreSQL для изолированной интеграционной проверки выясняется локально.
Если его нет, ограничение проверки записывается явно; рабочая БД не используется.
Миграция и полный diff проходят независимое ревью. Push и deploy не выполняются.

## Исключение чужих изменений

В рабочем дереве уже есть незакоммиченная уборка. Не включать ее в коммиты
реализации. Каждый пункт tasks.md получает отдельный коммит только своих файлов.

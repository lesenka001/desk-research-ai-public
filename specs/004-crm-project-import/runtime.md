## Настройка при внедрении

1. Установить зависимости из `requirements.txt` в среде приложения.
2. В закрытых настройках web задать `CRM_OWNER_PASSWORD` длиной от 12 символов.
   Значение не записывать в файлы репозитория, сообщения или историю команд.
   При пустом/коротком пароле `/crm` закрыт и возвращает 503; публичная лента
   продолжает работать. Регистрация и логин не требуются.
3. Для HTTPS оставить `CRM_COOKIE_SECURE=true` (значение по умолчанию).
   Только при локальном HTTP-разработке допускается `false`; это не настройка
   production. Две переменные уже передаются web через Compose.
4. Перед внедрением сохранить снимок действующего релиза по существующему
   процессу SPEC 003. Запуск web через `python main.py web` вызывает
   `db.init_schema`: аддитивно создает `crm_dataset` и `crm_history`, не меняя
   данные находок. Этот шаг сначала проверить на изолированной PostgreSQL.
5. Открыть `/crm`, войти и загрузить `.xlsx`. Система сохраняет корректные
   строки сразу и показывает результат; раздел «Проверка» содержит только
   спорные ЦА/выбросы. Принять решения, проверить проекты и историю.

Сессия действует до восьми часов; выход отзывает ее на сервере. Перезапуск web
завершает все текущие сессии, данные и решения остаются в PostgreSQL.
При смене пароля прежние cookies недействительны. Защищены все действия,
есть CSRF, SameSite/HttpOnly cookies, ограничение попыток входа и запрет кеширования.

Файл максимум 16 МБ, до 20 000 строк, распакованный XLSX до 64 МБ.
Файл читается в памяти, на диск сервера не записывается. Данные строк, причины
исключений и решения сохраняются в истории постоянно. История доступна порциями
по 30 событий, строки больших отчетов и проекты имеют постраничный просмотр.

- Контрольный Excel от 23 ноября обработан новым `read_xlsx` и `import_rows`
  в памяти, без БД: 539 строк, 25 исключений, 514 сохраненных PN.
  485 приняты сразу, 29 волн с отличающейся ЦА ожидают решения. При повторе:
  514 неизмененных, 25 исключенных, 29 ожидающих; состояние побайтно логически
  равно исходному снимку, новые проекты/вопросы не создаются.
- 21 трекер имеет отличия текста ЦА после безопасной нормализации. Отдельная
  диагностическая проверка IQR по 21 группе одинакового текста кандидатов не нашла.
  До решений владельца предварительные группы не следует считать окончательными.
- Проверены нормализация с сохранением диапазонов/десятичных чисел/`+`/`%`/
  отрицаний; обычное округление; порядок PN; неизменные повторные импорты;
  спорная замена и решения; формулы и структура XLSX; конфликтующие PN.
- HTTP-тесты запускают настоящий локальный `ThreadingHTTPServer` с тестовым
  хранилищем: вход, закрытый доступ, подделка/срок/смена пароля сессии, отзыв
  при выходе, CSRF/Origin, загрузка, решение ЦА, проекты/история, XSS-экранирование.
- Хранилище проверено транзакционной моделью: блокировка перед чтением,
  атомарный снимок+история, откат при ошибке истории, отсутствие БД-вызова при
  поврежденном файле. Это не подмена интеграционной проверки PostgreSQL.

## Независимое ревью

Ревью `crm_review` проверило миграцию, хранилище, расчеты, XLSX и интерфейс.
Устранены замечания:

- Постоянные исключения деактивируют и прежний принятый PN; история сохраняется,
  исправленная последующая выгрузка восстанавливает проект. Конфликтующие
  дубли сами по себе отклоняются только из текущего файла.
- При замене единственного PN прежняя принятая ЦА показывается рядом и доступна
  в выборе «Это та же ЦА».
- Выход отзывает серверную сессию, повтор старой cookie не дает доступа.

Повторное ревью исправлений: новых замечаний нет, семь HTTP-тестов повторены
проверяющим успешно. Полный набор 184 тестов выполнен основным агентом.

## Непроверенные границы перед внедрением

- PostgreSQL/Docker/psql локально не найдены. Реальные SQL, повторный старт схемы,
  транзакции/конкуренцию и сохранность после перезапуска PostgreSQL необходимо
  проверить на отдельной тестовой БД до production. Рабочая БД не использовалась.
- Визуальная проверка страницы не завершена: браузерный host недоступен,
  попытка Computer Use вернула `Computer Use was not approved to use Google Chrome`.
  Доступ не обходился. HTTP-сценарии проверены; вид на компьютере/телефоне
  нужно проверить в браузере перед внедрением.
- Для IQR две–три волны не выявляют выброс при выбранных линейных квартилях;
  отсутствие отметок не подтверждает содержательную сопоставимость проектов.
- Снимок JSONB сериализует ежемесячные загрузки блокировкой одной строки.
  Это осознанное минимальное решение для одного загрузчика; больших нагрузок
  и длинной многолетней истории локальная квартальная выборка не проверяет.

Откат к предыдущему коду не требует удаления двух новых CRM-таблиц: старый код
их не использует. Историю и загруженные данные при откате не удалять.

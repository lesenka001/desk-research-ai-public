# Задачи SPEC 005

Статус: SPEC утверждена 26 ноября 2026 года. План и задачи подготовлены;
T1–T3 реализованы локально, T4 открыта. [Спецификация](spec.md), [план](plan.md).
Одна задача — один коммит, только изменения этой задачи.

- [x] T1 — Доменная логика типа и групп (`005-T1`).
  Файлы: `crm/domain.py`, `tests/test_crm_domain.py`.
  Добавить независимый от IR учет известных пар «аорг»/PN, постоянные номера
  групп, необязательные названия, каталог групп с полными описаниями/PN/статусами.
  Сохранить правила SPEC 004 и старые ключи соответствий. Подготовить чистую
  функцию дополнения старого снимка сведениями истории для T2.
  Готово: тесты всех статусов, повторов, двух ЦА одного трекера, группы без IR,
  стабильности номеров и переименования проходят; расчеты и сопоставления прежние.
  Покрывает критерии SPEC 1–7, 9, 12–13 на уровне логики.

- [x] T2 — Сохранение и совместимость старых данных (`005-T2`).
  Файлы: `crm/store.py`, `tests/test_crm_store.py`; доменные исправления
  и тесты при необходимости. Схему SQL сохранять, пока JSONB и существующие
  виды событий достаточны; при обнаруженной необходимости изменения сообщить
  владельцу до коммита.
  Инициализировать дополнения старого снимка под блокировкой с учетом всей
  истории импорта, сохранять номера, названия и известные пары. Добавить
  атомарное переименование с аудитом и проверкой актуальности.
  Готово: повторная инициализация не меняет результат, событие старше последних
  30 учитывается, ошибка откатывает снимок и историю; старые соответствия,
  принятые версии и решения сохранены. Проверено восстановление после перезапуска.
  Покрывает критерии 7, 9–10, 12–13 на уровне хранения.

- [x] T3 — Явный выбор и редактирование названий в интерфейсе (`005-T3`).
  Файлы: `web/crm.py`, `web/crm.css`, `tests/test_crm_web.py`.
  Вывести тип и счетчик в обеих точках, номера/названия групп, полные описания,
  связанные PN со статусами; сохранить просмотр групп без расчетного IR.
  Требовать явного выбора, отдельно создавать группу, показывать результат
  и необходимость проверки выброса. Добавить форму названия и историю решения.
  Готово: HTTP-путь третьей волны во вторую ЦА проходит; неверный/пустой выбор,
  устаревшие действия, отсутствие доступа/CSRF отклоняются; названия экранируются,
  изменения и очистка сохраняются; номера и тексты согласованы во всех местах.
  Покрывает критерии 3–8, 10–13 на уровне интерфейса.

- [ ] T4 — Общая приемка, независимое ревью и документация (`005-T4`).
  Файлы: тесты CRM при выявленных пробелах, `runtime.md` в этой папке,
  `README.md`, `PRD.md`, `KANBAN.md`, `PROGRESS.md`, `specs/README.md`,
  статусы документов SPEC 005.
  Пройти все 13 критериев, запустить полный набор тестов и `git diff --check`.
  Выполнить интеграционную проверку на отдельной PostgreSQL и визуальную приемку.
  Провести одно независимое ревью готового diff с обязательным разбором
  совместимости старых данных; устранить замечания с целевыми перепроверками.
  Готово: результаты и реальные ограничения записаны; нет необъясненных
  изменений расчетов, утраты истории или ложного заявления о deploy.
  Если PostgreSQL или визуальная приемка недоступны, отметить ограничения
  и оставить соответствующую приемку незавершенной.

Push, merge и deploy не включены. Рабочая БД и исходные Excel не используются
для изменения данных при разработке. Локальный launcher остается отложенным.

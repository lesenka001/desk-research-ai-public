# SPEC 005 / T5: исправления проверки ЦА после пользовательской приемки

Основание: прямые уточнения владельца 26 ноября 2026 года после просмотра
обновленной CRM. Это исправление текущей SPEC 005; положения ниже заменяют
прежнее обязательное указание единственной группы и видимый заголовок «ЦА N».
Владелец отдельно подтвердила: проверку оставлять, единственную ЦА выбирать
автоматически; не принимать содержательно спорную волну без подтверждения.

## Требуемое поведение

1. При одной существующей группе нет выпадающего списка. Действие «Это та же ЦА»
   относит волну к ней без дополнительного выбора; «Это другая ЦА» создает группу.
   Если групп несколько, владелец явно выбирает нужную. Проверка IQR отдельная.
2. Сохранение решения и загрузка возвращают в раздел проверки. Переименование
   сохраняет раздел проектов и поисковый запрос. Сохраняется номер страницы;
   если после последнего решения она опустела, показывается последняя непустая.
   Короткий результат находится в текущем разделе; перехода в историю нет.
3. Для сравнения игнорируются регистр, пунктуация и пробелы, включая различия
   «мужчины,женщины» / «мужчины женщины». Начальная часть до первого двоеточия
   исключается только из сравнения; исходный текст сохраняется полностью.
   Значимые числовые ограничения сохраняются: 18–45 не равно 1845,
   100+ не равно 100, 1,5 не равно 15; слова отрицания не удаляются.
4. Ранее сохраненные ключи групп, соответствия, ручные названия и решения IQR
   остаются прежними. Существующая очередь пересчитывается новым сравнением
   один раз при первом обращении после обновления, под блокировкой и с аудитом.
   Однозначно эквивалентные описания больше не требуют ручного решения.
   Ранее вручную разделенные группы автоматически не объединяются; новый
   текст, подходящий к нескольким таким группам, остается на проверке.
5. Вместо заголовка «ЦА N» показывается PN последней расчетной волны группы;
   если расчетных волн нет — последней известной по дате и числовой части PN.
   Ручное название показывается рядом и сохраняет возможность изменения.
   Внутренние номера и ключи сохраняются для совместимости, в заголовке их нет.
6. В эдхоке скрыт блок «Связанные PN», единственный PN не повторяется в соседней
   колонке. Нормализованно одинаковые описания одной группы выводятся один раз.
   У трекера связанные PN со статусами остаются доступными.

## Реализация и границы

Файлы: `crm/domain.py`, `crm/store.py`, `web/crm.py` и три существующих набора
тестов CRM. Новые сервисы, LLM и SQL-миграция не нужны. Прежний алгоритм ключа
сохраняется как `legacy_audience_key` для чтения существующих соответствий.
Сопоставление сначала уважает явную старую привязку, затем ищет единственный
вариант по новому правилу среди исходных описаний существующих групп.
JSONB получает `audience_matching_version=2`. Повторный доступ не повторяет
сохранение и событие пересчета. Ошибка истории откатывает обновление снимка.

Все исправления — одна задача T5 и один локальный коммит `005-T5`.
Перед коммитом: целевые регрессии, полный набор, независимое ревью изменения
нормализации/совместимости, `git diff --check`. Рабочая БД не используется;
push/deploy для этих исправлений не выполняются без указания владельца.

## Проверка результата

- Одна группа: кнопка совпадения работает без `target`, отдельная ЦА создается
  альтернативной кнопкой; несколько групп без выбора дают ошибку.
- После действия активна «Проверка», сообщение видно там же; после изменения
  названия остаются «Проекты и волны», поиск и доступная страница списка.
- Разные названия опции, пунктуация и интервалы между словами не создают спор,
  числа и содержательные ограничения продолжают различаться.
- Прежний снимок с legacy-ключами сохраняет группы/названия/принятые решения;
  эквивалентная ожидающая волна распознается без новой загрузки Excel.
- Заголовок группы содержит PN; эдхок показывает его один раз, без связанных PN;
  одинаковые тексты представлены одним описанием. Названия сохраняются.

Результаты прогонов и ограничения приемки дополняются в runtime.md.

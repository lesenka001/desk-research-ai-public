# Навигатор достижимости ЦА — база статистических находок

Учебный прототип собирает открытые исследования, извлекает проверяемые
процентные характеристики людей и показывает их в веб-интерфейсе и Telegram.
Абсолютные, денежные, рыночные и операционные показатели не попадают в текущую
ленту. Система пересчитывает вложенные доли относительно подтвержденной базовой
аудитории. Полноценная оценка IR по произвольному запросу в эту версию не входит.

```text
ФОМ / НАФИ / Data Insight / Банк России
                 ↓
              collector
                 ↓
              Postgres
                 ↓
          worker + OpenRouter
                 ↓
          web + Telegram bot
```

## Источники

| Источник | Доступ | Что собирается |
|---|---|---|
| ФОМ | RSS + HTML | опросы, таблицы, методология и аудитории |
| НАФИ | HTML-каталог + HTML | результаты открытых опросов |
| Data Insight | RSS + HTML | исследования потребительских аудиторий; рыночные показатели отфильтровываются worker |
| Банк России | RSS + HTML | только записи с исследовательскими и аудиторными ключевыми словами |

RSS используется для обнаружения URL. Collector дополнительно загружает
публичную HTML-страницу, очищает текст и сохраняет хеш содержимого.

## Что хранится в находке

- тема;
- тип показателя: `population_share` или `conditional_share`;
- роль в ленте: базовая, производная или условная находка;
- применимость для IR: `direct` или `indirect`;
- география;
- аудитория;
- показатель и значение;
- база процента;
- период исследования отдельно от даты публикации;
- период, срок или частота поведения отдельно от периода исследования;
- объяснение применимости для ЦА;
- дословный подтверждающий фрагмент;
- смысловой блок, родительская находка и порядок внутри блока;
- исходная условная доля, точный результат, формула и цепочка расчета;
- утвержденные таргетируемые критерии и неподтвержденные кандидаты;
- модель и версия промпта.

Один материал может содержать до 20 находок. Значение сохраняется только как
процент от явно подтверждённой группы людей: населения, респондентов,
пользователей, покупателей, работников, B2B-респондентов или другой аудитории.
Дословная цитата должна присутствовать в собранном тексте и содержать то же
значение и уточнение базы.

## Базовые, производные и условные доли

Утвержденный список критериев хранится в `worker/targeting_criteria.json`.
Первоначально в него входят география, пол, возраст, наличие детей, автомобиля,
водительских прав, кошек и собак, статус занятости, должность, отдел, отрасль,
сфера деятельности и размер бизнеса.

Если материал сообщает `38%` от подтверждённой базы людей, а затем `33%` внутри
этой группы, worker после проверки обеих цитат рассчитывает
`38% × 33% = 12,54%` и показывает `12,5%`. Если взаимоисключающие варианты одной
шкалы образуют новую базу, worker сначала складывает их: например,
`14% + 36% = 50%`, а затем использует `50%` как родителя производных находок.
Вопросы с множественным выбором не складываются.

Расчеты выполняются через `Decimal`. Для показа дробная часть `0–0,40`
округляется вниз, `0,41–0,59` — до `0,5`, `0,60–0,99` — вверх. Исходные
значения, точный результат, формулы, компоненты, цитаты и обоснование базы
остаются доступны в деталях.

Модель извлекает связи между находками, но не выполняет арифметику. Если связь
знаменателей неоднозначна, условная доля сохраняется без пересчета только при
наличии явного уточнения аудитории. Новый возможный критерий показывается
кандидатом; это не мешает арифметике по подтверждённой человеческой базе, но не
добавляет критерий в утверждённый список автоматически.

Лента группирует находки сначала по исходной странице, затем по независимым
смысловым блокам. Внутри блока сначала показываются компоненты и составная
базовая находка, затем производные по глубине цепочки и после них условные доли.
Унаследованный период не повторяется в каждой производной; собственный
отличающийся период уточняющего вопроса показывается обязательно.

## Локальный запуск

Нужны Python 3.12+ и PostgreSQL.

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните в `.env` как минимум:

```text
DATABASE_URL=postgresql://user:password@localhost:5432/desk_research
OPENROUTER_API_KEY=...
MODEL=anthropic/claude-haiku-5.5
```

Импортируйте переменные в текущую сессию PowerShell:

```powershell
Get-Content .env | ForEach-Object {
    if ($_ -and -not $_.StartsWith('#')) {
        $name, $value = $_ -split '=', 2
        [Environment]::SetEnvironmentVariable($name, $value, 'Process')
    }
}
```

Для первого теста уменьшите объем:

```powershell
$env:MAX_PER_SOURCE = '3'
$env:WORKER_BATCH_SIZE = '10'
```

Запуск блоков:

```powershell
python main.py collector
python main.py worker
python main.py web
python main.py bot
```

`collector` выполняет один проход и завершается. `worker`, `web` и `bot`
работают постоянно, поэтому запускайте их в отдельных окнах. Обычная веб-страница
доступна на `http://localhost:8000`, лента бота — на `http://localhost:8080`.

Telegram требует `TELEGRAM_TOKEN`. Для открытия локальной Mini App внутри
Telegram нужен публичный HTTPS-туннель и переменная `MINI_APP_URL`. Без токена
сервис `bot` все равно поднимает веб-ленту.

## Повторная обработка

Обычный перезапуск worker не обрабатывает материал повторно с той же версией
промпта. Версия компактного контракта, составных баз и производных —
`audience-composite-bases-v6`.

### Контрольный прогон в Coolify

Контроль выполняется только на материале `3`, «Продажа и покупка подержанных
товаров». Перед redeploy убедитесь, что он существует:

```sh
psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT id, title, processed_prompt_version FROM materials WHERE id = 3;"
```

В Environment Variables временно установите:

```text
PROMPT_VERSION=audience-composite-bases-v6
REPROCESS_OLD=1
REPROCESS_MATERIAL_IDS=3
MAX_FINDINGS_PER_MATERIAL=20
MAX_OUTPUT_TOKENS=12000
```

Сохраните переменные и выполните redeploy. После завершения worker проверьте
результат запросом:

```sh
psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT count(*) FILTER (WHERE NOT f.is_derived AND f.parent_finding_index IS NULL AND f.base_kind IN ('targetable_explicit','targetable_inferred')) AS base_count, count(*) FILTER (WHERE f.is_derived) AS derived_count, count(*) FILTER (WHERE NOT f.is_derived AND NOT (f.parent_finding_index IS NULL AND f.base_kind IN ('targetable_explicit','targetable_inferred'))) AS conditional_count FROM findings f WHERE f.prompt_version='audience-composite-bases-v6' AND f.material_id=3;"

psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT f.block_index, f.block_position, CASE WHEN f.is_derived THEN 'Производная' WHEN f.parent_finding_index IS NULL AND f.base_kind IN ('targetable_explicit','targetable_inferred') THEN 'Базовая' ELSE 'Условная' END AS role, f.value, f.source_value, f.calculated_percent, f.calculation_formula, f.composite_component_indices FROM findings f WHERE f.prompt_version='audience-composite-bases-v6' AND f.material_id=3 ORDER BY f.block_index, f.block_position;"

psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT status, structured_mode, candidate_count, accepted_count, rejected_count, error FROM processing_attempts WHERE material_id=3 AND prompt_version='audience-composite-bases-v6' ORDER BY id DESC LIMIT 1;"
```

Ожидаемый результат:

- ровно 14 текущих находок: 4 базовые, 10 производных, 0 условных;
- составная база `50%` имеет формулу `14% + 36% = 50%` и ссылки на оба
  компонента;
- производные покупки: `10,5%`, `7%`, `7%`, `17,5%`, `16,5%`;
- производные продажи: `6%`, `4%`, `4%`, `12%`, `9%`;
- Mini App показывает два смысловых блока, составную базу перед производными и
  детали точных расчетов без дублей исходных условных процентов;
- Telegram показывает 4 базовые и 10 производных находок без условных;
- предыдущие версии материала остаются в базе для аудита, но не попадают в
  текущую ленту.

Сразу после проверки верните безопасный обычный режим и снова выполните
redeploy:

```text
REPROCESS_OLD=0
REPROCESS_MATERIAL_IDS=
```

В обычном режиме именно эти два значения должны оставаться такими: worker
обрабатывает только новые материалы и не запускает старые повторно.

### Полный архив

Пустой `REPROCESS_MATERIAL_IDS` при `REPROCESS_OLD=1` означает повторную
обработку всего архива. Эту комбинацию нельзя включать после контрольного
прогона автоматически. Полный архив запускается только после отдельного
подтверждения пользователя, что контрольные цифры и экран выглядят правильно.
Обычные новые материалы обрабатываются независимо от контрольного списка.

Новая интерпретация становится текущей только после успешного ответа модели.
Предыдущие версии находок остаются в базе для проверки истории, но не выводятся
в текущей ленте. Ошибка модели не удаляет предыдущие находки.

## Тесты

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

Тесты проверяют HTML/RSS-адаптеры, дедупликацию, допустимые типы показателей,
дословность подтверждения, блоки, родительские связи, расчеты через `Decimal`,
округление, безопасный отказ от неоднозначного расчета и отображение в Mini App,
Telegram и web.

После настройки `OPENROUTER_API_KEY` можно проверить модель на восьми свежих
публикациях без записи в базу:

```powershell
$env:QUALITY_ITEMS_PER_SOURCE = '2'
python quality_check.py
```

Скрипт самостоятельно записывает `quality_report.json` в UTF-8, не пропуская
кириллицу через кодировку PowerShell. Не перенаправляйте его вывод через
`Tee-Object`: в консоли печатается только краткая сводка и путь к отчету.
Для каждого материала используется строгая JSON Schema OpenRouter. При пустом,
обрезанном, невалидном JSON или отсутствии совместимого strict-endpoint
выполняется одна повторная попытка в совместимом режиме `json_object`. Повторная
ошибка записывается в отчет со статусом `error`, после чего проверка продолжает
следующую публикацию.

Для дешевой проверки одной публикации установите `QUALITY_TOTAL_ITEMS=1`.
Отчет quality check содержит уже проверенные расчетные значения и их формулы,
но ничего не записывает в PostgreSQL.

## Coolify

Публикация и развертывание выполняются после локальной проверки. В репозитории
сохранены `Dockerfile` и `docker-compose.yml`. Для ежедневного сбора в Coolify
нужно настроить задачу:

```text
python main.py collector
```

Рекомендуемое расписание — один раз в сутки. Секреты `.env`, токены, внутренние
Excel-файлы и дампы базы нельзя добавлять в Git.

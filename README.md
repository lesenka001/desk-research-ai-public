# Навигатор достижимости ЦА — база статистических находок

Учебный прототип собирает открытые исследования, извлекает проверяемые
процентные характеристики людей и показывает их в веб-интерфейсе и Telegram.
Абсолютные, денежные, рыночные и операционные показатели не попадают в текущую
ленту. Значения показываются так, как они приведены в исходной статье, без
пересчёта вложенных долей. Полноценная оценка IR по произвольному запросу в эту
версию не входит.

```text
ФОМ / НАФИ / Data Insight / Банк России
                 ↓
              collector
                 ↓
              Postgres
                 ↓
          worker + Open WebUI
                 ↓
          web + Telegram bot
```

## Источники

| Источник | Доступ | Что собирается |
|---|---|---|
| ФОМ | RSS + HTML | опросы, таблицы, методология и аудитории |
| НАФИ | HTML-каталог + HTML | результаты открытых опросов |
| Data Insight | RSS + HTML | исследования потребительских аудиторий; рыночные показатели отфильтровываются worker |
| Банк России | RSS + HTML | только записи с исследовательскими и аудиторными ключевыми словами |

RSS используется для обнаружения URL. Collector дополнительно загружает
публичную HTML-страницу, очищает текст и сохраняет хеш содержимого.

## Что хранится в находке

- тема;
- тип показателя: `population_share` или `conditional_share`;
- применимость для IR: `direct` или `indirect`;
- география;
- аудитория;
- показатель и значение;
- база процента;
- период исследования отдельно от даты публикации;
- период, срок или частота поведения отдельно от периода исследования;
- объяснение применимости для ЦА;
- дословный подтверждающий фрагмент;
- смысловой блок, родительская находка и порядок внутри блока;
- утвержденные таргетируемые критерии и неподтвержденные кандидаты;
- модель и версия промпта.

Один материал может содержать до 20 находок. Значение сохраняется только как
процент от явно подтверждённой группы людей: населения, респондентов,
пользователей, покупателей, работников, B2B-респондентов или другой аудитории.
Дословная цитата должна присутствовать в собранном тексте и содержать то же
значение и уточнение базы.

## Представление долей

Утвержденный список критериев хранится в `worker/targeting_criteria.json`.
Первоначально в него входят география, пол, возраст, наличие детей, автомобиля,
водительских прав, кошек и собак, статус занятости, должность, отдел, отрасль,
сфера деятельности и размер бизнеса.

Если материал сообщает `50%` среди взрослых россиян, а затем `21%` среди
покупателей, в ленте остаются исходные `50%` и `21%`. База каждой доли и цитата
хранятся отдельно. Новый возможный критерий показывается кандидатом и не
добавляется в утверждённый список автоматически.

Лента группирует находки сначала по исходной странице, затем по смысловым
блокам и перечисляет их в порядке исходного материала. Ролевого деления на
базовые, производные и условные находки нет.

## Локальный запуск

Нужны Python 3.12+ и PostgreSQL.

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните в `.env` как минимум:

```text
DATABASE_URL=postgresql://user:password@localhost:5432/desk_research
OPENWEBUI_BASE_URL=https://inside.omirussia.ru
OPENWEBUI_API_KEY=...
MODEL=qwen3.8-27b
MAX_OUTPUT_TOKENS=10000
MAX_FINDINGS_PER_MATERIAL=20
PROMPT_VERSION=audience-targetable-bases-v6
```

Для Qwen worker отключает рассуждения через `chat_template_kwargs.enable_thinking=false` и ожидает ответ API до 240 секунд.
Контрольный отчёт показывает `reasoning_tokens` и сообщает, если рассуждения Qwen не отключились или API не вернул счётчик.
Промпт v5 сохраняет в формулировках период и дословную базу; простые словесные доли людей переводятся в проценты с исходным выражением в `source_value` и цитатой в `evidence` (например, «две трети» → «около 67%»).

Импортируйте переменные в текущую сессию PowerShell:

```powershell
Get-Content .env | ForEach-Object {
    if ($_ -and -not $_.StartsWith('#')) {
        $name, $value = $_ -split '=', 2
        [Environment]::SetEnvironmentVariable($name, $value, 'Process')
    }
}
```

Для первого теста уменьшите объем:

```powershell
$env:MAX_PER_SOURCE = '3'
$env:WORKER_BATCH_SIZE = '10'
```

Запуск блоков:

```powershell
python main.py collector
python main.py worker
python main.py web
python main.py bot
```

`collector` выполняет один проход и завершается. `worker`, `web` и `bot`
работают постоянно, поэтому запускайте их в отдельных окнах. Обычная веб-страница
доступна на `http://localhost:8000`, лента бота — на `http://localhost:8080`.

Telegram требует `TELEGRAM_TOKEN`. Для открытия локальной Mini App внутри
Telegram нужен публичный HTTPS-туннель и переменная `MINI_APP_URL`. Без токена
сервис `bot` все равно поднимает веб-ленту.

## Повторная обработка

Обычный перезапуск worker не обрабатывает материал повторно с той же версией
промпта. Версия строгого отбора долей людей — `audience-targetable-bases-v6`.

### Контрольный прогон в Coolify

Сначала выберите три старых материала: публикацию о покупке подержанных товаров
и два отрицательных контроля с рыночными показателями — `29` («Перспективы
агентной коммерции в России») и `30` («eGrocery бюллетень»). Номер первого
материала найдите в терминале контейнера `postgres`:

```sh
psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT id, title, processed_prompt_version FROM materials WHERE title ILIKE '%подержан%' OR id IN (29, 30) ORDER BY id;"
```

В Environment Variables установите, подставив найденный id вместо `<ID>`:

```text
PROMPT_VERSION=audience-targetable-bases-v6
REPROCESS_OLD=1
REPROCESS_MATERIAL_IDS=<ID>,29,30
MAX_FINDINGS_PER_MATERIAL=20
```

Сохраните переменные и выполните redeploy. После завершения worker проверьте
результат запросом:

```sh
psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT m.id, m.title, f.block_index, f.block_position, f.value, f.percent_base, f.summary FROM findings f JOIN materials m ON m.id=f.material_id WHERE f.prompt_version='audience-targetable-bases-v6' AND m.id IN (<ID>,29,30) ORDER BY m.id, f.block_index, f.block_position;"
```

Ожидаемый результат:

- у материала о подержанных товарах доли сохранены в тех значениях и с теми
  базами, которые указаны в статье, без умножения процентов;
- у материалов `29` и `30` нет прогнозов, объёмов заказов, среднего чека,
  темпов роста и других нечеловеческих показателей;
- Mini App показывает материал и его смысловые блоки без ролевых меток;
- повторно обработанные материалы с подходящими долями приходят в Telegram.

Сразу после проверки верните безопасный обычный режим и снова выполните
redeploy:

```text
REPROCESS_OLD=0
REPROCESS_MATERIAL_IDS=
```

### Полный архив

Пустой `REPROCESS_MATERIAL_IDS` при `REPROCESS_OLD=1` означает повторную
обработку всего архива. Эту комбинацию нельзя включать после контрольного
прогона автоматически. Полный архив запускается только после отдельного
подтверждения пользователя, что контрольные цифры и экран выглядят правильно.
Обычные новые материалы обрабатываются независимо от контрольного списка.

Новая интерпретация становится текущей только после успешного ответа модели.
Предыдущие версии находок остаются в базе для проверки истории, но не выводятся
в текущей ленте. Ошибка модели не удаляет предыдущие находки.

## Тесты

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

Тесты проверяют HTML/RSS-адаптеры, дедупликацию, допустимые типы показателей,
дословность подтверждения, блоки, сохранение исходных процентов без пересчёта и
отображение в Mini App, Telegram и web.

После настройки `OPENWEBUI_API_KEY` можно проверить модель на восьми свежих
публикациях без записи в базу:

```powershell
$env:QUALITY_ITEMS_PER_SOURCE = '2'
python quality_check.py
```

Скрипт самостоятельно записывает `quality_report.json` в UTF-8, не пропуская
кириллицу через кодировку PowerShell. Не перенаправляйте его вывод через
`Tee-Object`: в консоли печатается только краткая сводка и путь к отчету.
Для каждого материала используется строгая JSON Schema Open WebUI. При пустом,
обрезанном, невалидном JSON или отсутствии совместимого strict-endpoint
выполняется одна повторная попытка в совместимом режиме `json_object`. Повторная
ошибка записывается в отчет со статусом `error`, после чего проверка продолжает
следующую публикацию.

Для дешевой проверки одной публикации установите `QUALITY_TOTAL_ITEMS=1`.
Отчет quality check содержит проверенные исходные значения, но ничего не
записывает в PostgreSQL.

## Coolify

Публикация и развертывание выполняются после локальной проверки. В репозитории
сохранены `Dockerfile` и `docker-compose.yml`. Для ежедневного сбора в Coolify
нужно настроить задачу:

```text
python main.py collector
```

Рекомендуемое расписание — один раз в сутки. Секреты `.env`, токены, внутренние
Excel-файлы и дампы базы нельзя добавлять в Git.

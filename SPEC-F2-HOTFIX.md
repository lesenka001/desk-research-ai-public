# SPEC-F2-HOTFIX: восстановление Mini App после фильтрации долей

## Зачем это читателю

После внедрения фичи 2 Mini App отвечает `database unavailable`, поэтому читатель
не видит ленту находок. PostgreSQL при этом работает: страницу ломает SQL-фильтр,
в котором драйвер `psycopg` ошибочно принимает символ процента из регулярного
выражения за начало плейсхолдера.

Hotfix должен вернуть доступ к ленте без изменения правил отбора находок и без
запуска повторной обработки архива.

## Что меняется и в каких файлах

- `bot/main.py` — символ `%` в общем SQL-фильтре долей экранируется для
  `psycopg`, чтобы PostgreSQL по-прежнему получал регулярное выражение для
  значений вида `38%`.
- `tests/test_views.py` — добавляется регрессионный тест, который проверяет
  подготовку нового SQL-фильтра драйвером и не допускает повторения ошибки
  `only '%s', '%b', '%t' are allowed as placeholders`.

Другие правила классификации, расчёта, отображения и повторной обработки не
меняются.

## Как проверим

### Автоматически

- новый тест воспроизводит подготовку запроса через `psycopg` и проходит после
  экранирования процента;
- проходят все тесты репозитория;
- JavaScript шаблона Mini App проходит синтаксическую проверку.

### После redeploy

- в Runtime Logs контейнера `bot` больше нет ошибки про `%[`;
- Mini App открывает ленту вместо `database unavailable`;
- существующие процентные находки отображаются;
- обычный режим остаётся безопасным: `REPROCESS_OLD=0`.

## Задачи по порядку

### F2-H1. Исправить SQL-фильтр Mini App

1. Экранировать литеральный `%` в `CURRENT_AUDIENCE_FINDING_SQL` для обработки
   драйвером `psycopg`.
2. Добавить регрессионный тест подготовки запроса.
3. Запустить новый тест, все тесты репозитория и проверку JavaScript шаблона.
4. Сделать один коммит с номером `F2-H1` в сообщении.

**Тест:** запрос с фильтром долей подготавливается без исключения и сохраняет в
SQL регулярное выражение, которое требует знак `%` в конце значения.

## Открытые вопросы

Нет. `REPROCESS_OLD` не относится к этой ошибке и до успешной проверки hotfix
остаётся равным `0`.
